# 综合布线自动生成规则 V2.0

> **用途**：用于自动生成综合布线表、机柜上架图、设备端口连接关系及布线任务。
>
> **设计目标**：将“设备/设备组 + 端口能力 + 连接场景 + 自动分配策略 + 约束校验 + 异常处理”统一定义，使规则既适合人工配置，也适合 AI / 程序自动生成布线结果。
>
> **原始规则依据**：本文件基于原始《布线逻辑设计》整理，并在其基础上补充设备类型、接口匹配、组间拓扑、链路数量、端口占用、故障校验、自动分配优先级等规则。原始文件明确规定了接入服务器、安全设备、BMC、核心/汇聚到接入交换机、交换机互联等主要场景。fileciteturn0file0L1-L8

# 3. 核心原则

## 3.1 端口匹配原则

任何自动布线必须按照以下顺序判断：

```text
设备角色匹配
    ↓
端口用途匹配
    ↓
速率匹配
    ↓
介质类型匹配
    ↓
端口形态匹配
    ↓
端口当前状态
    ↓
端口是否已被预留
    ↓
拓扑规则
    ↓
自动分配优先级
```

禁止：

```text
只要端口空闲 → 直接连接
```

必须：

```text
空闲 + 类型匹配 + 速率匹配 + 介质匹配 + 拓扑允许
→ 才能进入候选端口池
```

# 4. 端口状态

所有端口统一使用：

```text
AVAILABLE       可使用
OCCUPIED        已使用
RESERVED        已预留
DISABLED        禁用
FAULT           故障
NOT_SUPPORTED   不支持当前连接
```

自动分配时：

```text
只允许 AVAILABLE
```

以下端口禁止自动使用：

```text
OCCUPIED
RESERVED
DISABLED
FAULT
NOT_SUPPORTED
```

---

# 5. 自动分配通用算法

所有场景优先使用统一算法。

```text
STEP 1  确认源设备和目标设备
STEP 2  确认连接场景
STEP 3  确认所需链路数量
STEP 4  获取源端候选端口
STEP 5  获取目标端候选端口
STEP 6  过滤端口能力不匹配项
STEP 7  过滤已占用/预留端口
STEP 8  按端口优先级排序
STEP 9  按拓扑规则配对
STEP 10 执行容量校验
STEP 11 生成链路
STEP 12 锁定端口
STEP 13 生成布线标签
STEP 14 输出异常信息
```

# 6. 默认端口排序规则

## 6.1 交换机普通端口

默认：

```text
slot编号升序
→ port编号升序
→ AVAILABLE优先
```

即：

```text
slot1/port1
slot1/port2
slot1/port3
...
slot2/port1
slot2/port2
...
```

原始规则要求交换机自动选择时从“0口/最小接口”开始判断，使用第一个空闲接口；本版本统一为“按设备实际端口编号升序，从最小可用端口开始”。fileciteturn0file0L9-L14

## 6.2 UPLINK端口

只能从：

```text
port_type = UPLINK
```

中选择。

排序：

```text
slot编号升序
→ port编号升序
```

## 6.3 BMC端口

只能选择：

```text
BMC
IPMI
```

不得将普通业务网口误作为BMC目标端口。

# 8. 场景 A1：单台交换机 → 单台服务器

## 8.1 输入

```yaml
source:
  type: SWITCH
  role: ACCESS
  port_type: DOWNLINK

destination:
  type: SERVER
  port_type: SERVICE
```

## 8.2 默认链路数量

```text
默认：1
```

如果用户明确指定：

```text
link_count = N
```

则生成 N 条链路，但必须检查服务器端可用接口数量。

## 8.3 源端自动规则

```text
从最小slot的最小端口开始
寻找AVAILABLE
找到第一个符合条件端口即使用
```

## 8.4 目标端自动规则

如果源交换机为10G：

```text
目标必须为10G接口
优先：
slot1/port1
slot2/port1
...
```

原始规则明确要求万兆交换机只能对接服务器10G接口。fileciteturn0file0L13-L14

如果源为1G：

```text
目标允许：
1G接口
```

如果源为25G/40G/100G：

```text
按照设备能力表进行精确速率匹配
```

禁止自动降速，除非设备能力明确声明该端口支持协商/Breakout/降速。

# 10. 场景 A3：交换机组 → 单服务器

## 10.1 默认拓扑

例如：

```text
SW01 ───── SERVER01
SW02 ───── SERVER01
```

默认：

```text
每台源交换机至少1条链路
```

如果源组有 N 台交换机：

```text
link_count = N
```

## 10.2 源端规则

每台交换机独立执行：

```text
从最小slot/最小port寻找AVAILABLE
```

任何一台没有端口：

```text
整体生成失败
```

不能只生成部分线路，除非用户选择：

```text
ALLOW_PARTIAL = true
```

## 10.3 服务器端规则

目标服务器需要至少 N 个匹配接口。

优先策略：

```text
优先不同slot
其次同slot不同port
```

例如：

```text
3台10G交换机
服务器：
slot1：2个10G
slot2：2个10G

分配：

SW01 → slot1/port1
SW02 → slot2/port1
SW03 → slot1/port2
```

原始规则已经定义了“优先不同slot，slot不足时使用同slot不同接口”的原则，本版本将其标准化为统一优先级。fileciteturn0file0L26-L27

# 12. 场景 A5：交换机组 → 服务器组

这是最重要的多设备场景之一。

## 12.1 默认原则

源组：

```text
SW01
SW02
...
SWN
```

目标组：

```text
SRV01
SRV02
...
SRVM
```

默认要求：

```text
每台源交换机至少有1条链路
每台服务器至少有1条链路
```

当 N ≠ M 时，不要求严格一一对应。

## 12.2 默认均衡算法

采用：

```text
轮询 + 最小端口优先 + 设备均衡
```

例如：

```text
交换机：SW01 SW02
服务器：SRV01 SRV02 SRV03 SRV04

生成：

SW01 → SRV01
SW02 → SRV02
SW01 → SRV03
SW02 → SRV04
```

如果服务器数量小于交换机数量：

```text
SW01 → SRV01
SW02 → SRV02
SW03 → SRV01
SW04 → SRV02
```

但必须检查：

```text
单台服务器接口容量
```

## 12.3 冗余模式

用户可选择：

```yaml
topology_mode:
  SIMPLE
  BALANCED
  REDUNDANT
```

REDUNDANT要求：

```text
同一服务器尽量连接不同交换机
```

例如：

```text
SRV01：
SW01 → NIC1
SW02 → NIC2
```

禁止：

```text
SW01 → NIC1
SW01 → NIC2
```

除非用户明确要求双链路到同一交换机。

# 14. 场景 A7：混合设备组 → 混合设备组

允许：

# 15. BMC管理网络

## 15.1 BMC单链路

```text
ACCESS_SWITCH_1G
        ↓
SERVER_BMC/IPMI
```

默认：

```text
交换机端：DOWNLINK
服务器端：BMC/IPMI
```

原始规则要求千兆接入交换机做BMC管理时，从交换机0接口开始顺序连接服务器IPMI/BMC接口。fileciteturn0file0L52-L54

## 15.2 BMC组

例如：

```text
SW-MGMT01 → SRV01-BMC
SW-MGMT01 → SRV02-BMC
SW-MGMT01 → SRV03-BMC
```

端口按：

```text
最小可用端口
```

顺序分配。

## 15.3 BMC禁止规则

禁止：

```text
BMC → 10G业务端口
BMC → UPLINK
BMC → PEER_LINK
```

## 16.1 端口类型

```text
CORE/AGG：
DOWNLINK

ACCESS：
UPLINK
```

源：

```text
最小slot
→ 最小port
→ AVAILABLE
```

目标：

```text
最小UPLINK
→ AVAILABLE
```

## 16.3 速率匹配

例如：

```text
CORE 10G DOWNLINK
→ ACCESS 10G UPLINK
```

如果核心端为100G：


# 19. 场景 C4：核心/汇聚组 → 接入交换机组

这是典型的多对多上联场景。

## 19.1 基础原则

如果：

```text
源组 = N
目标组 = M
```

默认要求：

```text
每台源交换机至少1条链路
每台目标交换机至少1条链路
```

## 19.2 推荐拓扑

当 N = M：

```text
CORE01 → ACCESS01
CORE02 → ACCESS02
```

同时为了提高冗余，可配置：

```text
CORE01 → ACCESS02
CORE02 → ACCESS01
```

最终形成交叉冗余。

## 19.3 自动算法

```text
STEP 1 为目标组设备排序
STEP 2 为源组设备排序
STEP 3 每台目标设备选择一个不同源设备
STEP 4 优先使用源设备最小可用端口
STEP 5 优先使用目标设备最小可用UPLINK
STEP 6 如果端口占用则继续寻找下一个
STEP 7 检查是否所有设备均有连接
```

原始规则要求组到组连接时，保证组内每台设备都有连接，并在接口被占用时继续寻找下一个可用接口。fileciteturn0file0L66-L69

# 20. 千兆接入交换机上联

当：

```text
CORE/AGG = 10G
ACCESS = 1G
```

不能直接根据“设备都属于交换机”生成连接。

必须检查：

```text
核心设备是否存在1G UPLINK/DOWNLINK
```

如果核心没有1G接口：

```text
10G → 1G
```

默认判定：

```text
INVALID_SPEED
```

除非设备端口明确支持：

```text
10G/1G AUTO NEGOTIATION
```

原始文件只定义了“允许按照相同原则连接千兆接入交换机”，但未明确速率协商规则，因此本项属于本版本新增校验规则。fileciteturn0file0L70-L74

# 21. 交换机组内互联

## 21.1 Peer-Link

两台同组交换机：

```text
SW01 ↔ SW02
```

自动选择：

```text
UPLINK最后两个可用端口
```

用途：

```text
PEER_LINK
```

原始规则明确规定两台相同交换机组内互联时，使用UPLINK和DOWNLINK最后两个端口分别作为Peer-Link和DAD。fileciteturn0file0L76-L80

## 21.2 DAD

第二条链路：

```text
SW01 ↔ SW02
```

用途：

```text
DAD
```

建议最终统一表达：

```yaml
group_interconnect:
  link_1:
    role: PEER_LINK
  link_2:
    role: DAD
```

---

# 22. 两台交换机组内互联的端口选择

默认优先级：

```text
1. 专用PEER_LINK端口
2. UPLINK最后两个端口
3. DOWNLINK最后两个端口
4. 用户指定端口
```

如果指定端口已占用：

```text
不得覆盖
→ 寻找备用端口
→ 如果无备用端口则报错
```


允许用户指定：

```text

source_port

destination_port
```

这是最高优先级。

## 23.2 自动模式

默认采用：

```text

→ 最后两个可用端口
→ 交叉连接
```

例如：

```text

```

原始规则要求组外核心之间自动连接时采用组后两个接口交叉互联。fileciteturn0file0L82-L84

# 24. 多链路场景

用户可以明确指定：

```yaml
link_count: 2
```

例如：

```text
CORE01 → ACCESS01

Link1
CORE01 port49 → ACCESS01 uplink1

Link2
CORE01 port50 → ACCESS01 uplink2
```

必须满足：

```text
源端口不能重复
目标端口不能重复
```

除非设备模型明确允许：

```text
BREAKOUT
PORT_CHANNEL
LAG
```

# 25. LAG/聚合链路

如果连接类型为：

```text
LAG
LACP
ETH-TRUNK
PORT_CHANNEL
```

则：

```text
link_count >= 2
```

所有链路必须属于同一个：

```yaml
aggregation_group:
  group_id: "LAG001"
  protocol: "LACP"
```

例如：

```text
CORE01/49 → ACCESS01/49
CORE01/50 → ACCESS01/50

aggregation_group = LAG001
```

# 28. 手动模式规则

手动模式必须：

```text
用户指定源端口
+
用户指定目标端口
```

系统只做校验，不自动替换。

校验：

```text
端口存在
端口未占用
端口未预留
端口类型正确
速率匹配
介质匹配
设备角色允许
```

如果失败：

```text
禁止生成
```

并返回明确错误。

# 29. 自动模式规则

自动模式：

```text
系统自动选择端口
```

用户可以指定约束：

```yaml
constraints:
  source_port_type: "DOWNLINK"
  destination_port_type: "UPLINK"
  speed: "10G"
  media: "SFP+"
  link_count: 2
  redundancy: true
```

系统不得违反用户约束。

# 30. 端口预留规则

```text
reserved_for:
  PEER_LINK

  BMC
  UPLINK
  LAG
  FUTURE
```

例如：

```yaml
port:
  port_id: "49"
  status: "RESERVED"
  reserved_for: "PEER_LINK"
```

普通布线自动分配时：

```text
禁止使用
```

## 31.2 组外关系

包括：

```text
UPLINK
```

# 32. 设备组连接数量规则

## 32.1 单组 → 单设备

默认：

```text
源组每台设备至少1条
```

## 32.2 单设备 → 单组

默认：

```text
目标组每台设备至少1条
```

## 32.3 组 → 组

默认：

```text
源组每台设备至少1条
目标组每台设备至少1条
```

## 32.4 冗余模式

如果：

```text
redundancy = true
```

则默认：

```text
每台目标设备至少连接2台不同源设备
```

前提：

```text
源设备数量 >= 2
目标设备端口 >= 2
```

否则报告：

```text
REDUNDANCY_CAPACITY_INSUFFICIENT
```

---

# 33. 组内设备不能重复占用同一物理链路

禁止：

```text
SW01 port1 → SRV01 port1
SW01 port1 → SRV02 port1
```

同一物理端口默认只能存在一条物理连接。

除非：

```text
PORT_SPLIT
BREAKOUT
```

---

# 34. 设备组连接的均衡原则

自动生成组间链路时：

```text
优先设备均衡
→ 再端口均衡
→ 再slot均衡
```

例如：

```text
CORE01：2条
CORE02：2条
CORE03：2条
```

优先于：

```text
CORE01：6条
CORE02：0条
CORE03：0条
```

除非用户指定：

```text
PRIMARY_DEVICE
```

---

# 35. 跨Slot冗余原则

对于服务器、多网卡设备：

```text
如果存在多个相同速率slot
```

冗余模式优先：

```text
NIC1 → SLOT1
NIC2 → SLOT2
```

避免：

```text
NIC1 → SLOT1
NIC2 → SLOT1
```

这样可以降低单板卡故障造成的链路同时中断风险。

# 36. 自动布线优先级

统一定义：

```text
P1 用户明确指定端口
P2 端口用途匹配
P3 速率完全匹配
P4 介质完全匹配
P5 设备冗余要求
P6 跨Slot
P7 设备均衡
P8 最小Slot
P9 最小Port
```

注意：

```text
P8/P9不能覆盖P2-P7
```

# 38. 典型异常场景

## 38.1 交换机无空闲端口

```text

提示：
设备 SW01 无可用DOWNLINK端口。
```

## 38.2 服务器没有匹配网卡

```text
结果：
ERROR = NO_MATCHING_PORT

提示：
服务器 SRV01 无可用10G接口。
```

## 38.3 UPLINK不足

```text
结果：
ERROR = INSUFFICIENT_UPLINK_CAPACITY

提示：
源设备组需要3个UPLINK，但目标交换机仅剩2个。
```

## 38.4 组间冗余不足

```text

ERROR = REDUNDANCY_NOT_SATISFIED

SRV01需要连接至少2台不同交换机，但当前仅有1台可用源交换机。
```

# 39. 自动生成前必须进行的容量计算

系统先计算：

```text
required_source_ports
required_destination_ports
```

再计算：

```text
available_source_ports
available_destination_ports
```

只有：

```text
available >= required
```

才允许进入正式分配。

避免：

```text
生成一半 → 发现端口不足 → 回滚
```

推荐采用：

```text
预检查
→ 模拟分配
→ 全量校验
→ 正式提交
```

# 40. 布线生成的事务机制

建议程序采用：

```text
PLAN
  ↓
VALIDATE
  ↓
ALLOCATE
  ↓
RECHECK
  ↓
COMMIT
```

任何阶段失败：

```text
ROLLBACK
```

不得留下部分占用状态。

---

# 41. 连线生成顺序

当一次生成任务包含多种链路时，推荐顺序：

```text
1. Peer-Link
2. DAD
3. 核心/汇聚互联
4. 核心/汇聚 → 接入
5. 接入 → 服务器/安全设备
6. BMC
7. 其他业务链路
```

原因：

```text
先固定高优先级/专用端口
→ 再分配普通端口
```

避免普通业务先占用Peer-Link、DAD或UPLINK。
